# VeloDrive 模块架构与工作原理

## 一、进程概览

项目由 **6 个进程** 组成：

| 进程 | 可执行文件 | 端口 | 职责 |
|------|-----------|:----:|------|
| API Gateway | `server` | 8848 | HTTP 入口、路由分发、OSS/MQ/JWT |
| Auth Service | `auth_service` | 8001 | 注册、登录 |
| File Service | `file_service` | 8002 | 文件列表查询 |
| Consumer | `consumer` | — | MQ 消费、OSS 备份 |
| Consul | (Docker) | 8500 | 服务注册与发现 |
| RabbitMQ | (Docker) | 5672 | 消息队列 |

## 三、完整请求链路

### 3.1 注册

```
浏览器
  │  POST /api/v1/auth/register  { username, password, confirm }
  ▼
server (:8848)
  │
  │  AccountHandler::register_user()
  │  ① 解析 JSON, 校验 Content-Type、参数
  │  ② 构造 Protobuf RegisterReq
  │  ③ ConsulManager::discover("AuthService") → "127.0.0.1:8001"
  │  ④ 创建 SRPCClient → auth_service
  │  ⑤ push 到 workflow series → 异步等待
  │
  ▼  sRPC TCP
auth_service (:8001)
  │
  │  AuthServiceImpl::Register()
  │  ① 校验参数
  │  ② CryptoUtil::generate_salt()    → 随机盐
  │  ③ CryptoUtil::hash_password()    → SHA-256(salt + password)
  │  ④ MySQL INSERT INTO tbl_user
  │  ⑤ 返回 RegisterResp { code=0, user_id=42, username }
  │
  ▼  sRPC TCP
server (:8848)
  │
  │  ⑥ callback: Protobuf → JSON
  │  ⑦ HTTP 201 { status:"success", data:{ userId:42, username } }
  │
  ▼
浏览器 ← 显示注册成功
```

### 3.2 登录

```
浏览器 → server → Consul 发现 AuthService → sRPC LoginReq → auth_service
  → MySQL SELECT tbl_user → CryptoUtil 验密码 → 生成 JWT
  → sRPC LoginResp { access_token } → server → JSON → 浏览器
```

### 3.3 文件列表

```
浏览器 → server → 本地 JWT 验证 → Consul 发现 FileService
  → sRPC ListFilesReq { uid } → file_service
  → MySQL SELECT tbl_file → 返回文件数组
  → server → JSON → 浏览器
```

### 3.4 文件上传

```
浏览器 → server (:8848)  ← 全程在网关完成，不经过微服务
  │
  │  FileHandler::upload_file()
  │  ① 本地 JWT 验证 → uid
  │  ② 接收 multipart/form-data
  │  ③ CryptoUtil::generate_hashcode() → 文件哈希
  │  ④ ofstream 写 ./storage/{hashcode}         ← 本地存盘
  │  ⑤ MqManager::publish("velo.direct", ...)    ← 发 MQ 消息
  │  ⑥ MySQL INSERT INTO tbl_file                 ← 数据库记录
  │  ⑦ HTTP 201
  │
  ▼
RabbitMQ
  │
  ▼
consumer
  │  ① MqManager::consumeOne() → 收到 hashcode
  │  ② 读 ./storage/{hashcode}
  │  ③ OssManager::putObject(hashcode, data)     ← 上传 OSS
  │  ④ 循环
```

### 3.5 文件下载

```
浏览器 → server (:8848)  ← 全程在网关完成
  │
  │  FileHandler::download_file()
  │  ① 验 JWT
  │  ② MySQL SELECT uid, filename, hashcode
  │  ③ 检查文件归属
  │  ④ stat("./storage/{hashcode}")
  │     ├── 存在 → resp->File(本地路径)
  │     └── 不存在 → OssManager::getObject(hashcode) → resp->String()
```

## 四、服务注册与发现流程

```
启动阶段：
  auth_service 启动
    → ConsulManager::registerService("AuthService", "127.0.0.1", 8001, "AuthService-8001")
    → Consul 记录：{ name:"AuthService", address:"127.0.0.1", port:8001 }
    → 定时心跳：每 9 秒 servicePass("AuthService-8001")

  file_service 启动
    → 同上，注册 FileService @ 127.0.0.1:8002

运行阶段：
  Gateway 收到请求
    → ConsulManager::discover("AuthService")
    → Consul API: GET /v1/health/service/AuthService?passing=true
    → 返回健康的实例列表 [{ address:"127.0.0.1", port:8001 }]
    → 创建 SRPCClient 连接

故障恢复：
  auth_service 进程崩溃
    → 心跳停止 → 10 秒后 TTL 超时 → Consul 标记 unhealthy
    → Gateway 下次 discover → 返回空列表 → 返回 500 给浏览器
  auth_service 重启
    → 重新注册 + 心跳 → Consul 标记 healthy
    → Gateway 又能发现并连接
```

## 五、数据库表结构

### tbl_user

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT PK | 用户 ID |
| username | VARCHAR(255) UNIQUE | 用户名 |
| password | VARCHAR(255) | 密码哈希值 |
| salt | VARCHAR(64) | 盐值 |
| created_at | DATETIME | 注册时间 |

### tbl_file

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT PK | 文件 ID |
| uid | INT FK | 所属用户 |
| filename | VARCHAR(255) | 文件名 |
| hashcode | VARCHAR(255) | SHA-256 文件哈希 |
| size | INT | 文件大小（字节） |
| created_at | DATETIME | 上传时间 |
| last_update | DATETIME | 最后更新时间 |

## 六、模块间的通信协议

```
浏览器 ↔ server      :  HTTP/JSON
server ↔ auth_service :  sRPC (TCP Protobuf)
server ↔ file_service :  sRPC (TCP Protobuf)
server → RabbitMQ     :  AMQP
RabbitMQ → consumer   :  AMQP
consumer → OSS        :  HTTPS
所有进程 → Consul     :  HTTP API (ppconsul 封装)
微服务 → MySQL        :  MySQL TCP (workflow 异步任务)
```
